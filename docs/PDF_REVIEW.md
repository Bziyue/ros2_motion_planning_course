# PDF 视觉复核流程

每次生成都要检查，并在交付前修复发现的问题。LaTeX 日志能发现部分溢出和缺字，
但不会告诉我们圆被拉扁、箭头被遮住、标注压在连线上，或图例挡住数据。

## 构建与查看

在仓库根目录运行：

~~~bash
make -C textbook
~~~

构建会调用 scripts/render_pdf_review.py，使用主机 Poppler 与 Pillow 生成：

| 文件 | 用途 |
| --- | --- |
| tmp/pdfs/review/course/index.html | 逐页浏览，点击图片打开 144 dpi 原图 |
| tmp/pdfs/review/course/pages/page-*.png | 全部页面，保持 PDF 页面的原始纵横比 |
| tmp/pdfs/review/course/sheet-*.png | 每张四页的联系表，用于全书初筛 |
| tmp/pdfs/review/course/CHECKLIST.md | 本次 PDF 的哈希、页数、日志提示及待完成清单 |

页号按 PDF 的物理顺序计数，包含封面和目录，不等于正文印刷页码。
大纲构建使用相同流程，输出在 tmp/pdfs/review/outline/。
依赖为 poppler-utils、python3-pil 与 DejaVu 字体；主机已具备，无需修改 ROS 环境。

## 每次必须完成的检查

1. 按用户后续要求，仅检查本次新增或修改章节，不重复浏览无改动的前面章节。
2. 在阅读大小查看本章页面，检查分页、边距、页眉页脚及意外空白；放大检查图、公式、表格和代码。
   公共样式、字体或跨页调整确实影响其他页面时，再检查受影响页。联系表只用于初筛。
3. 修复发现的问题，从源文件重新编译并渲染，再检查最新版的受影响页面，直到问题解决。
4. 在 docs/VALIDATION.md 记录页数、PDF 的 SHA-256、检查范围、问题和复核结果，
   再完成当前功能的提交。不能只写“编译成功”。

| 检查对象 | 具体看什么 |
| --- | --- |
| 图中的文字 | 不压线、不相互覆盖，与对应点、线或区域关系明确 |
| 线段与箭头 | 起终点正确；没有多画、弯折、遮挡或因白底标签造成的断线 |
| 几何形状 | 物理坐标等比例；圆仍是圆、方格仍是方格；圆弧半径符合公式 |
| 数据图 | 单位、刻度、图例可读；图例不挡住数据；比较条件与正文一致 |
| 截图 | 保持原始纵横比；界面文字和关键目标能辨认 |
| 公式、表格和代码 | 无缺字、裁切或异常字距；编号、行号、换行和表头正确 |
| 整页 | 页眉页脚不碰正文，图与图注不分离，相邻页没有意外重排 |

二维几何图使用相同的 x/y 单位长度。PGFPlots 可显式设置 axis equal image；
Matplotlib 可设置等比例坐标。只有图框的宽高相等，并不能保证两轴的物理比例相等。
TikZ 中分别写 draw=颜色、fill=颜色，避免后续颜色简写覆盖已经指定的填充。

## 放大细节与处理日志

例如单独放大 PDF 第 19 页（不是正文第 19 页）：

~~~bash
pdftoppm -f 19 -l 19 -r 220 -png output/pdf/course.pdf tmp/pdfs/detail
~~~

渲染脚本会收集 Overfull、Underfull 与 Missing character 提示。
缺字或溢出会让构建返回失败，但预览仍会生成，方便定位。
Underfull 要查看相应段落是否字距异常；没有提示的页也必须目视检查。
其他编译警告（如未定义引用）仍需阅读 LaTeX 日志并处理。

每次渲染会更新哈希并重置待办清单，防止把旧检查记录用于新 PDF。
检查者可以填写临时清单；提交的正式记录放在 docs/VALIDATION.md。
脚本只准备检查材料并检查部分日志，不能自动证明没有重叠或失真。

逐章编辑时可执行 `make -C textbook REVIEW_CHAPTER=1`（附录用A/B/C/D）。仍编译完整教材PDF，但只按PDF章节目标自动渲染对应物理页，页号保持全书编号；不填该变量仍渲染全文。章节标题增删造成的目录调整在本轮最终稿集中复核。
