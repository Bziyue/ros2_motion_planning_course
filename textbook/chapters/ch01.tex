\chapter{环境搭建与第一个圆盘场景}\label{ch:first}
\begin{notebox}
\textbf{本章目标}\quad 编译课程工作空间，理解节点怎样发送图形消息，在 RViz2 看见半径为 0.20 m 的圆盘。\\
\textbf{先修}\quad 会打开终端、编辑文本，读懂基本 C++ 变量和函数。

\section{先认识四个名字}
节点（node）是执行计算并收发消息的程序。话题（topic）是带名字和类型的数据通道，例如本章的 \code{/visualization/robot}。包（package）组织源码、依赖和安装规则。工作空间是存放和构建这些包的目录。例如本课程的 \code{ros2_ws} 中，src 存源码，build 存编译中间结果，install 存供 ROS 使用的程序和配置。

本章只有一个发布节点和一个可视化程序：
\begin{center}
\begin{tikzpicture}[node distance=28mm]

RViz2 将收到的几何消息绘制成图形；本章的位置和尺寸由发布节点给定，圆盘保持静止。

\section{确认主机环境}
本课程验证平台是 Ubuntu 26.04 和 ROS 2 Lyrical。已有主机不用重装。打开 bash，先运行：
\begin{lstlisting}[language=bash,numbers=none]
source /opt/ros/lyrical/setup.bash
printenv ROS_DISTRO
ros2 pkg prefix rviz2
colcon --help
\end{lstlisting}
前三项应分别加载环境、输出 lyrical、找到 RViz2。最后一项显示构建工具的帮助信息。若某条命令找不到，先解决这一项，再进入构建步骤。

干净主机应先按
\href{https://github.com/ros2/ros2_documentation/blob/rolling/source/Get-Started/Installation/Ubuntu-Install-Debs.rst}{ROS 官方安装步骤}
配置 UTF-8、Universe 与 ros-apt-source。已配好软件源的 Ubuntu 26.04 可安装
\code{ros-lyrical-desktop}、\code{ros-dev-tools}、\code{libeigen3-dev}。
不要把其他 Ubuntu 版本与 Lyrical 的二进制包混用。

\begin{notebox}
Lyrical 的 ROS 接口按 C++20 编译；本课程独立几何和数学代码采用 C++17。ROS 的 Python 包使用系统 Python，构建时显式指定 \code{/usr/bin/python3}。
\end{notebox}

\section{构建并启动}
以下路径是当前主机仓库位置；换机器后改成自己的路径。每个新终端都要先加载主机环境，再加载课程工作空间。
\begin{lstlisting}[language=bash,numbers=none]
source /opt/ros/lyrical/setup.bash
cd /home/zdp/ForCodex/ros2_motion_planning_course/ros2_ws
colcon build --symlink-install --cmake-args \
  -DCMAKE_BUILD_TYPE=RelWithDebInfo \
  -DPython3_EXECUTABLE=/usr/bin/python3
source install/setup.bash
ros2 launch motion2d_bringup ch01.launch.py
\end{lstlisting}
\code{motion2d} 保存算法和节点；\code{motion2d_bringup} 保存配置、launch 与 RViz2 视图。
后面用到的自定义消息集中在 \code{motion2d_interfaces} 包，本章先使用 ROS 已有的 Marker 类型。

\textbf{为什么要两次 source？}第一条加载主机的 ROS 环境，让终端找到 ros2 和基础包。
编译后的 install 目录是本课程新生成的一层环境；第二次 source 将这一层加入当前终端的查找路径。
可以把它理解为告诉终端：“除了系统程序，还到这个课程目录找程序。”每个新终端都要完成这两步。

\textbf{构建与启动分别做什么？}colcon 根据各包的依赖关系编译 C++，把可运行结果放到 install。
launch 再按照启动文件同时创建节点、加载 YAML 参数并打开 RViz2。
修改 C++ 后重新 build；修改 YAML 后重启节点。
\code{--symlink-install} 让安装目录中的配置链接到源码目录，方便编辑时保持两处一致。

RViz2 应显示浅色背景、0.5 m 网格和原点的青色圆盘，Fixed Frame 为 map。在只有终端的环境中，加 \code{rviz:=false} 启动节点，再用本章后面的 topic echo 查看同一条消息。

\section{圆盘为什么用直径？}
用一个很薄的 CYLINDER 表示圆盘。Marker 的 scale 是物体的完整尺寸，因此
\begin{equation}
d_x=d_y=2r,\qquad r=0.20\ \mathrm{m}\ \Rightarrow\ d_x=d_y=0.40\ \mathrm{m}.
\end{equation}
\code{scale.z=0.05} 只是显示厚度，后续平面碰撞只使用半径。圆柱的 position.z 是中心高度。取 0.025 m、厚度 0.05 m 时，下表面恰好落在 z=0。
orientation.w=1 且其他分量为零表示保持原始方向；第二章再说明平面旋转的表示。alpha 控制透明度，0 完全透明，1 完全不透明。

\paragraph{顺着消息读代码}
frame\_id=map 表示 position 中的 x/y 是地图坐标；换坐标系后，同样的两个数字通常表示另一个位置。
ns 与 id 共同标识这个图形，后续以同一标识发布会更新它。
type 选择圆柱，action=ADD 让 RViz 创建或更新图形。
最后 publish(disk) 把整个结构体作为一条消息发出，所以接收者能一次取得同一图形的位置、尺寸和颜色。

程序入口先调用 rclcpp::init 初始化通信，再构造 HelloScene。
构造函数读取参数并发布圆盘；spin 让节点继续运行，保存发布者及其消息缓存。
在终端按 Ctrl+C 后结束 spin，程序清理通信资源并退出。

\section{发布一次，为什么晚启动也能看到？}
QoS 是双方约定的传输方式。reliable 表示可靠传输；transient-local 让运行中的发布者保存最近一条消息。
本节点和 RViz2 使用相同的持久性设置。先启动节点，过几秒再打开 RViz2，它就能取得缓存的圆盘。
这种方式适合静态场景和配置；后面连续传感器数据会采用不同的队列与传输设置。

第二个终端加载环境，进入工作空间后运行：
\begin{lstlisting}[language=bash,numbers=none]
ros2 topic echo /visualization/robot --once \
  --qos-durability transient_local
/usr/bin/python3 ../scripts/check_ch01.py
\end{lstlisting}
检查程序确实作为晚加入的订阅者接收消息，并核对帧、类型与默认尺寸。此时消息 stamp 用系统时间；下一章再引入仿真时钟。

\section{动手修改第一个场景}
\begin{enumerate}
\item \textbf{理解：}节点与话题的区别是什么？发布者先启动、RViz2 后启动时，为什么仍能收到圆盘？
\item \textbf{代码：}完成 \code{exercises/ch01/starter/marker_scale.hpp} 中的
\code{EXERCISE(ch01-1)}。检查方法、分级提示和独立参考答案位于同目录。
\item \textbf{实验：}在 \code{ch01.yaml} 中把半径改成 0.35 m、x 改为 1.0 m，重启。先预测消息和网格上的尺寸，再观察；完成观察后恢复默认参数，便于后续章节使用相同起点。
\end{enumerate}
应看到直径 0.70 m、圆心 $(1,0)$ 的圆盘。若图形不见了，依次检查 Fixed Frame、话题、alpha 与 QoS。若找不到包，检查是否加载课程的 install 环境。
