\section{哪些计算可以同时进行}
一次瞬时扫描使用同一位姿和同一静态世界。第 $i$ 束的方向为
\[
 \theta_i=\psi+\theta_{\min}+i\Delta\theta,\qquad d_i=(\cos\theta_i,\sin\theta_i).
\]
它只需要找自己与障碍物的最近非负交点，与相邻光束的结果无关。
CPU 逐束循环时，一个束算完才进入下一束；GPU 可以把许多束交给不同线程，同时执行同一求交函数。
\textbf{线程}在这里就是负责一个束索引的执行实例；\textbf{内核}是这些线程共同执行的 GPU 函数。
CPU 负责准备数据、启动内核和取得结果，GPU 负责批量求交。

设扫描有 $B$ 束、$C$ 个圆和 $E$ 条线段。每束分别检查 $C+E$ 个对象，
总求交次数为 $B(C+E)$，因此总工作量随两者乘积增长，记为 $O(B(C+E))$。
本实现保持每束内部的遍历顺序，只把束之间的工作并行化。
增加障碍数会增加每个线程的工作，增加束数则会增加可分配的线程数。

\section{从线程块位置得到光束编号}
线程按块组织。设每块 $K$ 个线程，块编号 $b$、块内编号 $j$ 都从零开始，
前面 $b$ 个块已经覆盖 $bK$ 个索引，因此全局索引是
\[
 i=bK+j,\qquad 0\le j<K.
\]
覆盖 $B$ 束需要最小整数块数 $G$ 满足 $GK\ge B$，即
\[
 G=\left\lceil B/K\right\rceil
  =\left\lfloor(B+K-1)/K\right\rfloor.
\]
最后一种形式适合正整数除法。代码取 $K=128$；$B=720$ 时启动 6 块、768 个线程，
索引 0--719 计算，720--767 直接返回。每个有效线程只写 \code{ranges[i]}，彼此没有写冲突。

\subsection{圆求交仍使用第 05 章的几何}
令圆心相对射线起点的向量为 $q=c-o$，单位方向为 $d$，
沿束投影 $h=q\cdot d$，垂直分量 $\ell=d_xq_y-d_yq_x$。
把 $\|td-q\|^2=r^2$ 分解为平行和垂直两个分量，得到
\[
 (t-h)^2+\ell^2=r^2,\qquad t_\pm=h\pm\sqrt{r^2-\ell^2}.
\]
判别式负则未相交；否则先试较小根 $t_-$，它非负时就是入口；较小根在身后时再试较大根。
例如 $o=(0,0),d=(1,0),c=(3,0),r=1$，两根为 2、4 m，取 2 m；
从圆心发射时两根为 $-1,1$ m，取出口 1 m。
练习 ch20-1 正是把这段根选择写成普通 C++，再与内核中的 \code{circleHit} 对照。

\section{把静态几何放在设备上重复使用}
CPU 内存和 GPU 设备内存各自保存数据。构造 \code{CudaLidar} 时，把世界中的圆和多边形边展开，
外框也作为四条边加入。设备数组依次存放
\[
 [c_x\ (C),\ c_y\ (C),\ r\ (C),\ a_x\ (E),\ a_y\ (E),\ b_x\ (E),\ b_y\ (E)],
\]
括号内是元素个数。将同一字段连续存放称为结构分量数组（SoA）。
例如 $a_x$ 起始偏移为 $3C$，$a_y$ 为 $3C+E$；内核中的指针加法正是在计算这些偏移。
总元素数为 $3C+4E$，每个 double 占 8 字节，因此几何占 $8(3C+4E)$ 字节。
$C=8$、8 个四边形加外框给出 $E=36$，共 1344 字节；720 个 float 输出另占 2880 字节。

\section{先对齐数值，再比较速度}
两后端使用同一个 \code{LidarConfig}。全周间隔为 $2\pi/B$；部分视场包含两端。
瞬时位姿、圆心安装、近于最小量程的 NaN 和超出最大量程的 $+\infty$ 都保持第 05 章含义。
例如 NaN 表示这一束测量无效，$+\infty$ 表示量程内没有回波，建图时处理方式不同。

设备几何用 double，输出转为 float。本章构建关闭 FMA 融合和 fast-math，
便于用同一运算过程检查数值误差。先逐束比较特殊值类别，再对有限量程计算
\[
 e_{\max}=\max_{i\in\mathcal F}|r_i^{\rm CPU}-r_i^{\rm GPU}|,
\]
$\mathcal F$ 是两者都有限的索引集合。比较阈值取 $2\times10^{-5}$ m。
圆相切、圆内发射、共线边、部分视场以及随机自由位姿分别检查求交的不同分支。

有噪声比较采用同一份按束编号排列的误差 $e_i$，分别调用两次 \code{perturbRange}：
\[
 \tilde r_i^{\rm CPU}=g(r_i^{\rm CPU},e_i),\qquad
 \tilde r_i^{\rm GPU}=g(r_i^{\rm GPU},e_i).
\]
这样距离差反映计算后端的差异。若两边独立采样，且暂不考虑量程裁剪，
即使理想距离相同，也有
$\operatorname{Var}[(r+n_1)-(r+n_2)]=\sigma^2+\sigma^2=2\sigma^2$，
差值标准差为 $\sqrt2\sigma$。$\sigma=0.01$ m 时约为 1.41 cm，远大于数值比较阈值。
固定种子还能帮助重放，但必须连同抽样次数、顺序及特殊值分支一起固定。

\section{加速收益为何随规模变化}
将一次驻留扫描分成启动与同步、求交内核、距离回传三部分。用简化模型理解交点：
设 $M=C+E$，CPU 每次求交平均成本为 $a$，GPU 单线程每次求交平均成本为 $g$，
有效同时工作的线程数为 $P$，固定开销为 $L$，每束回传成本为 $d$，则
\[
 T_{\rm CPU}\approx aBM,\qquad
 T_{\rm GPU}\approx L+gM\left\lceil B/P\right\rceil+dB.
\]
$P$ 表示特定内核、设备和规模下的有效并行度，可通过测量估计。
当 $B\gg P$ 时，用 $B/P$ 近似取整项，GPU 更快的条件变为
\[
 B\,[aM-gM/P-d]>L.
\]
若方括号为正，束数超过 $L/(aM-gM/P-d)$ 后才可能抵消固定开销；
若 $B$ 很少，只增加障碍物仍只启动少量线程。
这个模型解释趋势，具体交点还受缓存、分支和设备算术吞吐影响，应按实际扫描规模测量。

\subsection{如何读计时结果}
内核启动通常先返回 CPU，随后 GPU 才完成计算。
\code{CudaLidar::scan} 用两个 CUDA 事件包住内核并等待结束，以测设备执行时间；
用单调墙钟测量同步后的回传和整次调用。扫描计时包括启动、同步与回传。
关于事件与传输计时可参照
\href{https://docs.nvidia.com/cuda/cuda-c-best-practices-guide/index.html}{NVIDIA 性能测量指南}。

每组先预热 20 次，再测 60 次。预热使设备初始化与常用路径进入稳定工作状态。
把时长排序为 $t_{(0)}\le\cdots\le t_{(n-1)}$，基准程序采用
\[
 P_q=t_{(\lfloor q(n-1)\rfloor)}.
\]
因此 60 次测量的 P50 取索引 29，P95 取索引 56。P50 描述常见耗时，P95 帮助观察较慢样本。
本组设备为 RTX 5060，CUDA 13.2.1；圆与四边形各占障碍数的一半，外框另有四条边。
同组 CPU/GPU 使用相同位姿与几何，扫描时间从已生成的世界开始计算。

\subsection{为什么内核加速会逐渐遇到上限}
噪声和消息仍由 CPU 处理。若原来总时间中可加速部分占 $f$，该部分加速 $s$ 倍，
其余部分保持原耗时，则归一化新耗时为 $(1-f)+f/s$，整体加速比是
\[
 S=\frac1{(1-f)+f/s}.
\]
例如求交占 80\%，内核快 8 倍，整体只快 $1/(0.2+0.8/8)=3.33$ 倍；
即使求交耗时趋于零，整体也最多趋于 5 倍。
表中大束数的噪声阶段已占较大比例，可以先检查随机数与内存访问，再决定下一个优化对象。
重复测量时同时记录设备负载、预热次数和诊断开关；这些条件会改变实际时间分布。

\section{练习：让每个加速比都有明确含义}
\begin{enumerate}
\item 对 90、720、4096 束手算 128 线程一块时的块数、无效线程数和末束的块内编号。
\item \textbf{代码 ch20-1：}补全最近非负圆交点。检查前向命中、相切、圆内出口、未命中和根在身后。
\item 写出 $C=8,E=36$ 时各字段偏移，计算几何字节数及 16384 束输出大小。
\item 从独立零均值噪声推导差值方差 $2\sigma^2$，解释配对比较为何复用同一噪声数组。
\item 用两张计时表分别计算扫描和发布过程的加速比；固定几何逐步增加束数，找出本机交点。
\item 推导摊销 setup 和整体加速公式。若求交只占总时间一半，即使它快 10 倍，整体能快多少？
\item 先逐帧相加、再算 P50/P95；比较诊断开关的耗时影响，并区分采集时间和执行耗时。
\end{enumerate}
练习入口、判分项和手算提示见 \code{exercises/ch20/README.md}。
