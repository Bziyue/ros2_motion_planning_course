# 第20章：从逐束计算到完整扫描加速

1. 手算 90、720、4096 束、每块128线程时的块数、无效线程数、末束的块号与块内编号。用教材的18束小图检查索引算法。
2. **EXERCISE(ch20-1)**：补齐 `starter/ray_circle.hpp` 的最近非负根。这是内核代数的普通C++版本，无CUDA设备也可完成。

```bash
mkdir -p tmp
c++ -std=c++17 -I exercises/ch20/starter exercises/ch20/check_circle.cpp -o tmp/ch20-circle
./tmp/ch20-circle
```

前向命中、相切、圆内出口、完全未命中、根在后方各20%。参考解在 `solutions`，所有距离都以米计。

3. 对8个圆、8个四边形及外框，写出SoA各字段偏移。计算几何、720束输出和16384束输出的字节数。
4. 从独立噪声方差相加推导两后端差值标准差。解释复用相同误差数组、固定种子与逐束特殊值检查各自解决什么问题。
5. 运行 `lidar_cuda_benchmark`，按90/720/4096/16384束和0/16/128/512障碍比较完整扫描。先核对特殊值类别与最大有限误差，再报告setup、内核、回传、驻留扫描的P50/P95。
6. 从串行部分与可加速部分的耗时推导整体加速比。求交占一半、加速10倍时，整体快多少？setup为60ms、每帧扫描0.1ms时，10帧和1000帧的平均成本分别是多少？
7. 手算三帧阶段耗时(1,5)、(5,1)、(9,9)ms的各阶段中位数与总中位数。基准代码用排序索引floor(q(n-1))；60次测量P50/P95各取哪个索引？
8. `python3 scripts/run_ch20.py` 配对比较三个束数的ROS输出。区分采集stamp、发布线程耗时、订阅者延迟；固定场景分别打开/关闭lidar.profile，记录计时开销。

每组记录设备、编译选项、场景、束数、预热/采样次数和原始CSV。解释小束数GPU较慢的原因，再选一个实际占时较多的阶段提出优化方案。
